# 顾客端响应式修订 · 2026-10-05

当前规则替代此前“所有视口固定9:16”的布局。只根据可用视口和方向选择展示方式，不识别手机型号，不改变身份或路由。

## 布局规则

| 视口条件 | 顾客界面 |
|---|---|
| 默认窄屏竖向视口 | 9:16容器，按宽高可用空间缩放，必要留白；内容内部滚动 |
| 宽度至少768px且高度至少600px | 平板/电脑宽版，容器最大1320px，取消9:16限制 |
| 宽度至少1100px且高度至少600px | 首页餐品4列；分类/店铺餐品3列；手册目录3列 |
| 横屏、宽度至少480px且高度不超过599px | 紧凑宽版，取消9:16限制，保留内部滚动和全部功能 |
| 上述横屏宽度480–599px | 首页2列，分类与详情单列，避免小手机横屏挤压 |

平板宽版首页餐品3列；分类、店铺餐品、订单、店铺目录、信用卡片和资料使用适合内容的多列布局。商品详情使用图库与信息双栏。购物车、结算、资料表单采用有最大阅读宽度的宽栏。登录页也展开，不再套窄手机框。

所有布局仍使用 `/mall/…` 顾客页面；旧 `/front/…` 深链接转入相应顾客路由。商家和平台后台仍独立。仅在用户明确选择其他身份时进入相应后台。

页面顶部演示提示条按实际高度测量，避免横竖屏切换或文字换行时挤出容器。底部导航和操作栏跟随顾客容器；评价、退款、地址和还款弹层在容器内滚动。

客服聊天采用独立消息滚动区域与正常文档流中的输入区，附件选择区有最大高度并可滚动，避免覆盖消息。

## 检查结果及范围

- 44个当前/旧顾客路由实际Vue DOM渲染检查通过，包括首页、分类、店铺、商品、购物车、结算、地址、订单、信用、售后、评论编辑、客服、资料、登录返回目标与身份分离
- CSS声明、媒体条件与级联检查通过：390×844、430×932、480×599、767×600、768×1024、820×1180、1024×768、1440×900、844×390、568×320、768×599、768×600
- 检查确认竖屏/宽版/紧凑横屏规则、旧important规则覆盖、聊天滚动结构、页头预留高度以及懒加载组件的scoped样式优先级
- 完整前端回归和生产构建通过；实际Vue→Java客服/留言HTTP联调在本次布局修改后再次通过，原Java业务实现未修改

CSS检查是对声明与媒体匹配的验证，不是布局引擎测量。JSDOM验证路由和页面事件，不能证明真实像素、字体、可见性、触控面积、键盘弹出或安全区效果。本轮浏览器预览受到本地预览访问和浏览器启动限制，未完成实际手机/平板浏览器截图或视觉验收，不能将这些项记为通过。

## 修改文件

- `src/style/customer-responsive.css`：统一响应式规则
- `src/main.js`：在基础样式之后加载修订规则
- `src/views/Mall.vue`：顾客页面标识、首页/图库/订单/商家列表布局容器
- `src/App.vue`：演示提示条实际高度测量
- `src/components/AfterSalesCustomer.vue`：售后布局标识
- `src/components/SupportCustomer.vue`：发送后滚动到消息区域
- `tests/responsive-routes.test.mjs`、`tests/responsive-css-policy.test.mjs`：专项回归
